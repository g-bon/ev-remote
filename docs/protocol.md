# Stellantis connected-car protocol (MyOpel / MyPeugeot / …)

This is how EV Remote talks to the Stellantis (ex PSA) back end. It was reconstructed from the open source projects [psa_car_controller](https://github.com/flobz/psa_car_controller) (GPL-3.0) and [homeassistant-stellantis-vehicles](https://github.com/andreadegiovine/homeassistant-stellantis-vehicles) (MIT), and verified against the real servers.

Stellantis offers no public API for car owners. The app uses the OAuth client of the official mobile app (`client_id`, `client_secret`, realm). These values are **not** stored in this repository: the build downloads `configs.json` from the Home Assistant integration at a pinned commit and checks its SHA-256 (see [build.gradle](../android/app/build.gradle)).

## Servers

| Host | Role |
|---|---|
| `id-dcr.<brand>.com` | Login page (SAP Gigya, with reCAPTCHA) |
| `idpcvs.<brand>.com` | OAuth 2 (ForgeRock AM): authorize and token |
| `api.groupe-psa.com` | REST API: vehicles, status, user, SMS, MQTT token |
| `otp.mpsa.com` | inWebo OTP server (`/iwws/MAC`) |
| `mwa.mpsa.com:8885` | MQTT broker for remote commands (TLS) |

The servers answer in well under a second. Slow commands are slow because of the server-to-car leg (see "Command lifecycle").

## 1. OAuth login

1. Open `https://idpcvs.<brand>.com/am/oauth2/authorize?client_id=…&response_type=code&redirect_uri=<scheme>://oauth2redirect/<culture>&scope=openid%20profile%20email&locale=<locale>`.
2. The Gigya page asks for email and password, then shows a "login completed" page with a **Continue** button.
3. **Continue** redirects to `<scheme>://oauth2redirect/<culture>?code=…` (for MyOpel the scheme is `mymopsdk`). A desktop browser cannot open that scheme, so it looks like nothing happens. The app intercepts the redirect inside its WebView.
4. Exchange the code within a few minutes: `POST https://idpcvs.<brand>.com/am/oauth2/access_token?redirect_uri=…&grant_type=authorization_code&code=…`, with headers `Authorization: Basic base64(client_id:client_secret)` and `Content-Type: application/x-www-form-urlencoded`, and an empty body.
5. Refresh with the same endpoint and `grant_type=refresh_token&refresh_token=…`. The refresh token **rotates** on every use.

## 2. Account and vehicle

Every call carries `?client_id=…&locale=…`.

| Call | Headers | Notes |
|---|---|---|
| `GET /connectedcar/v4/user/vehicles` | `Authorization: Bearer`, `x-introspect-realm` | `_embedded.vehicles[]`: `id`, `vin`, `motorization`, `brand`, `pictures[]` |
| `GET /connectedcar/v4/user/vehicles/{id}/status` | same | full status (below) |
| `GET /applications/cvs/v4/mauv/car-associations` | Bearer, `User-Agent: okhttp/4.8.0`, `Accept: application/hal+json`, realm, `x-transaction-id: 1234` | `[0].customer` is the **customer id** used in the MQTT topics |
| `POST /applications/cvs/v4/mobile/smsCode` | same as car-associations | sends the SMS for the OTP activation |

Useful status fields:

| Data | JSON path |
|---|---|
| Battery % | `energies[type=Electric].level` |
| Range km | `energies[type=Electric].autonomy` |
| Charging status | `energies[Electric].extension.electric.charging.status` (`InProgress`, `Stopped`, `Finished`, `Disconnected`, `Failure`) |
| Plugged | `….charging.plugged` |
| Scheduled charging time | `….charging.nextDelayedTime` (e.g. `PT22H30M`) |
| Remaining time | `….charging.remainingTime` |
| Native 80% limit active | `….charging.type = Partial` |
| Climate | `preconditioning.airConditioning.status` (`Enabled`, `Disabled`, `Finished`). Sometimes spelled `preconditionning` |
| Climate programs | `preconditioning.airConditioning.programs[]`: `slot`, `enabled`, `occurence.day[]`, `start` |
| Outside temperature | `environment.air.temp` |
| Odometer | `odometer.mileage` |
| Locks | `doorsState.lockedStates[]` (`Locked`, `Unlocked`, …) |
| Open doors | `doorsState.opening[]`: `identifier` (`Driver`, `Passenger`, `RearLeft`, `RearRight`, `Trunk`) and `state` |
| GPS position | `lastPosition.geometry.coordinates` = `[lon, lat, alt]`, timestamp in `lastPosition.properties.createdAt`. On some cars it is never updated: check the timestamp |
| Moving, speed | `kinetic.moving`, `kinetic.speed` (same caveat as the position) |
| Ignition | `ignition.type`: `StartUp` on, `Stop` off |
| 12 V battery | `battery.voltage`: despite the name it is a **percentage** |
| Battery health | `energies[Electric].extension.electric.battery.health.capacity` / `.resistance` |

Other endpoints: `GET /connectedcar/v4/user/vehicles/{id}/trips` (trips, paginated) and `GET /applications/cvs/v4/rights/vehicle/{vin}` (subscribed services).

## 3. inWebo OTP (enabling remote commands)

Remote commands need an MQTT token, which is obtained with an OTP code generated by an inWebo "device" registered on the account. Implementation: [Otp.java](../android/app/src/main/java/it/gbon/evremote/Otp.java), [OtpCrypto.java](../android/app/src/main/java/it/gbon/evremote/OtpCrypto.java). It is a port of `otp.py` from psa_car_controller, and [otp-test](../android/otp-test) checks that both produce identical requests.

**Activation (once per device):**
1. `POST smsCode`: Stellantis sends an SMS to the phone number of the account.
2. `GET https://otp.mpsa.com/iwws/MAC?action=ActionSetup&mode=activate&code=<SMS>&macid=…`. The XML answer contains `Kfact` (server RSA modulus) and `Kiw` (client RSA modulus, encrypted).
3. `ActionFinalize`, mode `activate`, with:
   - `serial` = `device_id/_/iwalea`;
   - `Kma` = first 16 bytes of SHA-256(`PIN;serial`), RSA-OAEP encrypted with `Kiw`;
   - `pin`, encrypted with `Kiw`;
   - `R0`, `R1`, `R2`, SHA-256 challenge responses.

   The answer contains `K0` and `K1` (AES-ECB encrypted with Kma), `ms_key`, `ms_id` and `s_id`.
4. Mode `ms`: a random 16-byte secret is encrypted with the temporary server key, and with AES(Kma) for local storage (`iwsecval`).

**Generating a code** (whenever a new MQTT token is needed):
1. `ActionSetup`, mode `otp`, with `sid`: returns a `challenge`.
2. `ActionFinalize`, mode `otp`: returns `defi`. If the answer contains `J`, repeat once.
3. Code = base36 (alphabet `a-z0-9`, least significant digit first) of `((h[0:4] & 0xfffffff) * 1024) + (h[4:8] & 1023)`, where `h` = SHA-256(`K1:defi:iwsecval`).

Details that matter:
- The RSA exponent is 17.
- OAEP uses SHA-256 for both the hash and MGF1.
- `Kiw` and `ms_key` are "decrypted" with the **public** key, in 128-byte blocks.
- After activation, `action = "synchro"` is persisted and changes `R2` (which includes the PIN) for all later codes.
- The state must be saved after every code.
- Stellantis accepts about 6 codes per day, and each activation registers one more device on the account. Too many devices fail with `NOK:MAXNBTOOLS`.

## 4. MQTT token

`POST https://api.groupe-psa.com/connectedcar/v4/virtualkey/remoteaccess/token?client_id=…&locale=…`, with the car-associations headers and a JSON body:
- first token: `{"grant_type": "password", "password": "<OTP code>"}`;
- refresh: `{"grant_type": "refresh_token", "refresh_token": "…"}`.

The refresh token is treated as valid for 3 days. After that a new OTP code is needed.

## 5. Remote commands over MQTT

Broker connection:
- `ssl://mwa.mpsa.com:8885`, MQTT 3.1.1, clean session;
- user `IMA_OAUTH_ACCESS_TOKEN`, password = MQTT token;
- **empty client id**: the broker rejects arbitrary ids with "Invalid client ID";
- subscriptions:
  - `psa/RemoteServices/to/cid/<customer_id>/#` for command responses;
  - `psa/RemoteServices/events/MPHRTServices/<VIN>` for live vehicle events.

Publish to `psa/RemoteServices/from/cid/<customer_id><service>`:

```json
{"access_token": "<MQTT token>", "customer_id": "…", "correlation_id": "<uuid hex + yyyyMMddHHmmssSSS>",
 "req_date": "2026-01-01T18:00:00Z", "vin": "…", "req_parameters": { … }}
```

| Command | Service | `req_parameters` |
|---|---|---|
| Wake up (refresh status) | `/VehCharge/state` | `{"action": "state"}` |
| Climate on / off | `/ThermalPrecond` | `{"asap": "activate"/"deactivate", "programs": {program1..4}}`. Send back the current programs, otherwise they are erased |
| Charge now / stop | `/VehCharge` | `{"program": {"hour": h, "minute": m}, "type": "immediate"/"delayed"}`, using `nextDelayedTime` |
| Native charge limit | `/VehCharge/limit` | `{"action": …}` |
| Doors, horn, lights | `/Doors`, `/Horn`, `/Lights` | Not available with the basic e-Remote service |

Responses arrive with the same `correlation_id` and a `return_code` or `process_code`. Responses to commands sent by other apps on the same account (e.g. the official app) arrive on the same topic.

**Code 0 means the car accepted the command, not that the climate is running.** The REST status often lags behind the car: use the live events to confirm.

### Live events

Every event is a full state snapshot and events can arrive out of order. Useful fields:
- `precond_state.status`: 0 off, 1 on, 2 finished;
- `charging_state.hmi_state`: 1 charging, 3 complete;
- `charging_state.cable_detected`: **inverted**, 0 = plugged;
- `soc_batt`: lags and spikes, prefer the REST value;
- `sev_state`: 0 car off, 1 or 2 on;
- `doors_state.doors_locking_state`: 1 or 7 locked, 0 or 3 unlocked.

## Command lifecycle

| Code | Meaning |
|---|---|
| 900 | Accepted by the server |
| 901 | Car asleep, waking up (typically 20-50 s) |
| 902 | Checking status |
| 903 | Forwarded to the car |
| 0 / 1 | Done |
| 300 | Timeout: the car did not answer |
| 400 | Invalid MQTT token: refresh it and resend once. With `reason` `…no.matching.service.key`, the command is not supported by the car |
| 422 | Privacy mode active on the car |
| 500 | Error, see `resp_data.error` |
| 502 / 506 / 507 | Duplicate / unsupported mobile operator / no GPS |

`resp_data.error` for `/ThermalPrecond`:
- 0: car switched on;
- 1: already running;
- 2: communication problem (worth retrying);
- 3: stop refused, car on;
- 4: on activation the car is unlocked (it must be locked); on deactivation the climate was not running.

`resp_data.error` for `/VehCharge*`:
- 0: standby;
- 1: already charging;
- 2: communication problem;
- 3: car on.

Waking up a car that is already on returns 500 with `error = 4`. The climate stops by itself shortly after the car is unlocked or switched on.

## Limits

- **Wake-ups:** at most 6 every 20 minutes (client-side, as in the HA integration).
- **OTP codes:** about 6 per day.
- **OTP devices per account:** limited, error `NOK:MAXNBTOOLS`.
- **Climate:** needs the battery at 20% or more, or the car charging (HA integration rule), and the car **locked and off**.
